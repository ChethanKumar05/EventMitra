# EventMitra Postman setup

1. Import `EventMitra.postman_collection.json` and `EventMitra.local.postman_environment.json`.
2. Select EventMitra - Local. Set base_url if needed (default http://localhost:3600, no trailing slash).
3. Set admin_email/admin_password to your own super admin and new_admin_password to a private
   password for the sample admin (minimum 12 characters). Supplied credential values are empty.
4. Run `npm run migrate`, then `npm run admin:bootstrap` if the first super admin does not exist.
   Start the server with `npm run dev`.
5. Run folders in order: Health, Authentication, Roles, Admins, Main modules, Per-admin module
   permissions, Cleanup/logout. Public venues are independent. Login uses the cookie jar; keep it enabled.

Bodies show JSON fields directly. Replace field values yourself or use the environment variables.
The collection resolves strings safely, including passwords containing quotes and backslashes.
Create responses capture role_id, admin_id, module_id and permission_id. Codes are generated by
the API: ADM, RL, MOD and PER prefixes. Login and auth/me return effective module action flags.

The flow assigns flags to the selected admin and current role in admin_permission; there are no
submodules. The matrix save atomically replaces that admin's grant set, preserving IDs of existing
rows. Cleanup removes only the sample assignment, module, admin and role, then logs out.
Use a development database for a full run. To inspect records, stop before the cleanup folder.

List requests include page/limit and disabled optional search_column, search, sort_by, sort_order
and field filters in Params. Enable the ones you need. Changing an admin's role clears grants
and revokes sessions; reassign permissions for the new role. Security writes require super admins.

Reimport the collection to replace the previous role-permission catalog flow. Legacy catalog
endpoints remain on the server for compatibility but are not used for runtime authorization.

[API docs](../admin-api.md) | [Copyable payloads](../api-payloads.md) | [Lists](../list-api.md)

Updated login accepts admin_login (email or username); admin_email remains a fallback. New admin bodies include required admin_username. Permission create/update is now one POST /admin-permissions with a visible array body and HTTP 200 response. It preserves existing IDs and omitted flags. No separate per-record PUT request remains. Reimport the collection and environment for these changes.

Owner authentication has its own collection and environment, independent of the admin flow:
[Owner collection](EventMitra.Owner.postman_collection.json),
[Owner environment](EventMitra.Owner.local.postman_environment.json).
See [owner login/logout setup and test instructions](../owner-auth.md). Run only the folder
for your chosen login method; shared owner names must use email.

The Owner collection now includes Signup, email/phone Send OTP + Verify OTP, and email/phone Forgot Password + Reset Password folders. Test OTP is 1111; no email/SMS delivery is connected. See [Owner signup/OTP](../owner-signup-otp.md). Signup first, then verify. Names must be unique after migration 012.

User signup and phone OTP login have a separate [User collection](EventMitra.User.postman_collection.json) and [User environment](EventMitra.User.local.postman_environment.json). Apply migration 013, select **EventMitra - User Local**, and fill `user_name`, `country_code`, `user_phone_number` (optional `user_email`). Run signup once, then Login, Resend OTP and Logout folders. Tokens are saved automatically; keep the cookie jar enabled. Both login and resend accept `country_code` + `user_phone_number`; verify accepts `otp` + `otp_token`. The test OTP is `1111`, and these OTP endpoints are disabled in production. See [User flow and copyable bodies](../user-auth.md).
